# WS C web (landing + leaderboard app) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Public landing page (`/`) with a live weekly-token hero and install instructions, plus a logged-in leaderboard SPA (`/app`) with user detail and device management, both served as static assets from `packages/worker/public`.

**Architecture:** Vanilla HTML + CSS + ES modules, no build step. Pure data-shaping logic lives in `public/js/lib/*.js` and is unit-tested with vitest from `packages/worker/test/web/`. IO lives in `public/js/api.js`, which swaps to fixture responses from `public/js/mock-data.js` when mock mode is on (`?mock=1`, persisted in `sessionStorage`). Views render DOM with small helpers; charts are hand-built SVG (heatmap, sparkline, share bars, stacked breakdown) plus uPlot for the daily trend.

**Tech Stack:** HTML, CSS custom properties (OKLCH), ES modules, uPlot 1.6 (vendored into `public/vendor/`), Google Fonts (Geist, Geist Mono), vitest 4.1.

**Spec:** `docs/superpowers/specs/2026-09-24-leaderborder-design.md` (section "Web (Hallmark)") and master plan `docs/superpowers/plans/2026-09-24-leaderborder.md` (Contracts 3, 4, 6).

## Global Constraints

- JavaScript ESM only, no TypeScript, no framework, no build step, no new deps, no `npm install`.
- Zero comments by default; the only allowed comment is the Hallmark stamp at the top of CSS files.
- Never use U+2014 / U+2013. Plain hyphen only. All copy in English.
- Honest copy: no invented metrics. Landing numbers come only from `GET /api/public/stats`; skeleton while loading, a labelled placeholder on error.
- Edit only `packages/worker/public/**`, `packages/worker/scripts/**`, `packages/worker/test/web/**`, `.hallmark/**`, this file.
- No commit, push, stash, checkout, reset, worktree. Only `git add` own files.
- Asset URLs are absolute (`/css/...`, `/js/...`) because the Worker serves `app.html` for `/app` and `/app/*`.
- Mobile first: 320/375/414/768 px with no horizontal scroll; `html, body { overflow-x: clip }`; charts scroll inside their card.
- `prefers-reduced-motion` collapses motion to <=150 ms opacity.
- `tokens.css` defines every Contract 6 name; page CSS references tokens only.
- `npm run lint` passes; web tests pass.

## Design decisions (Hallmark)

- Initial pick was genre atmospheric / theme Bloom. User redirect (too much orange): re-routed to a tuned custom theme in the modern-minimal register. Genre modern-minimal, theme custom, vibe "clean instrument panel, one blue signal", axes light / geometric-sans / cool-blue.
- Palette (light): paper `oklch(98.6% 0.003 255)`, ink `oklch(19% 0.018 262)`, accent `oklch(56% 0.2 260)`, hairline rules `oklch(91.5% 0.006 256)`. Dark (`prefers-color-scheme` + `data-theme`): paper `oklch(15.5% 0.008 262)`, ink `oklch(96% 0.005 255)`, accent `oklch(68% 0.17 258)`. Blue sequential heat ramp `--heat-0..4`, blue-family client series `--series-1..5` + neutral `--series-other`, a single cool glow behind the hero figure only. No warm blooms.
- Type: Geist 600 display, Geist 400 body, Geist Mono for numbers, commands and code; tabular numerals everywhere. Radii 6/8/12 px, pill only for the floating nav.
- Macrostructure 04 Stat-Led. Hero: live `tokensThisWeek` figure (count-up) paired with a worded headline, a four-stat strip (all-time tokens, players, active this week, cost this week), a 90-day heatmap with derived facts (busiest day, average day, active days).
- Nav N5 floating pill. Footer Ft5 statement. Sections: hero, how it works (F4 step sequence), tools (list with live weekly share from `topClients`), install (primary `npx` block + alternates, copy buttons, DMG note), privacy (sent vs never sent, F3 spec sheet), final CTA, footer.
- Motion primitives (max 3): hero number tick, button press, copy-button label swap.
- Client colour follows entity: `claude`=1, `codex`=2, `cursor`=3, `gemini`=4, `opencode`=5, anything else = neutral "other".

### Task 2: Pure libs with tests (TDD)

**Files:** `public/js/lib/*.js`, `test/web/*.test.js`.

**Interfaces (Produces):**
- `formatCompact(1_234_567_890) === "1.2B"`, `formatCompact(340_000_000) === "340M"`, `formatCompact(12_400) === "12.4K"`, `formatCompact(812) === "812"`, `formatCompact(999_950) === "1M"`, `formatCompact(0) === "0"`, non-finite -> `"-"`.
- `formatUsd(1234.5) === "$1,235"`, `formatUsd(12.4) === "$12.40"`, `formatUsd(0.004) === "$0.00"`; `formatMetric("cost", v)` uses `formatUsd`, others `formatCompact`.
- `formatInteger(1234567) === "1,234,567"`.
- `formatDay("2026-09-24") === "Sep 24, 2026"`; `formatRange({ start: "2026-09-18", end: "2026-09-24" }) === "Sep 18 - Sep 24"`.
- `relativeTime(iso, now)`: `"just now"` < 1 min, `"5 min ago"`, `"3 h ago"`, `"2 d ago"`, null -> `"never"`.
- `periodLabel("week") === "Last 7 days"`, `"day" -> "Today"`, `"month" -> "This month"`, `"all" -> "All time"`; `metricLabel("tokens_nocache") === "Tokens without cache"`; `metricKey("tokens_nocache") === "tokensNoCache"`, `"cost" -> "costUsd"`, `"tokens" -> "tokens"`.
- `isoDay(date)` local `YYYY-MM-DD`; `addDays("2026-03-01", -1) === "2026-02-28"`; `dayRange("2026-09-24", 3)` -> `["2026-09-22","2026-09-23","2026-09-24"]`.
- `buildHeatmap(daily, { end, days, key = "tokens" })`: fills missing days with 0, columns are Monday-start weeks, leading cells before the range are `null`, each cell `{ day, value, level }` with `level` 0 for 0 and 1-4 by quartile of the max (`levelFor(v, max) = v <= 0 ? 0 : Math.min(4, Math.ceil((v / max) * 4))`), `months` = `[{ col, label }]` for the first column of each month.
- `clientSlot("claude") === 1` ... `"opencode" -> 5`, unknown -> `"other"`.
- `shareSegments({ claude: 60, codex: 30, amp: 10 })` -> `[{ client:"claude", value:60, fraction:0.6, slot:1 }, { client:"codex", ... }, { client:"amp", slot:"other", ... }]` sorted desc, zero values dropped, total 0 -> `[]`; `limit` folds the tail into `{ client: "other" }`.
- `parseRoute("/app", "")` -> `{ name: "leaderboard" }`; `"/app/u/ada"` -> `{ name: "user", login: "ada" }`; `"/app/devices"` -> `{ name: "devices" }`; `"/app.html", "#/u/ada"` -> user ada; `"/app.html", "#/devices"` -> devices; unknown -> `{ name: "not_found" }`; login decoded and validated `^[A-Za-z0-9-]{1,39}$`.
- `routeMode("/app.html") === "hash"`, `routeMode("/app/u/x") === "path"`; `routeHref({ name: "user", login: "ada" }, "path") === "/app/u/ada"`, same in hash mode -> `"#/u/ada"`; leaderboard -> `"/app"` / `"#/"`.
- `sparklinePath([0, 10, 5], { width: 100, height: 20, pad: 2 })` -> `"M2 18L50 2L98 10"` (values scaled into padded box; all zero -> flat line at bottom; single value -> horizontal line).
- `groupByClient(rows, "tokens")` -> `[{ client, total, slot, models: [{ model, value, fraction }] }]` sorted desc by total, models sorted desc, fraction of client total.
- `filtersFromSearch("?period=month&metric=cost&client=codex")` -> `{ period:"month", metric:"cost", client:"codex", model:"" }` with invalid values falling back to defaults (`week`, `tokens`); `leaderboardQuery(filters)` -> `"period=month&metric=cost&client=codex"` omitting empty.

- [x] Write each `test/web/<module>.test.js` with the cases above, run `npx vitest run test/web` from `packages/worker` (temporary `--root` / `--config` fallback if WS B's config is missing), watch them fail, implement, rerun green.
