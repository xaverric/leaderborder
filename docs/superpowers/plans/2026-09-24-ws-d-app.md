# WS D - Electron menubar app Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** macOS menubar app (Tray + frameless popover) on top of the `leaderborder` core that shows today/week tokens, rank and sync status, runs periodic syncs and handles GitHub device login and Cursor connect.

**Architecture:** `main.js` is thin wiring of Electron APIs. All behaviour lives in small injected-dependency modules: `scheduler.js` (timers, single-flight), `view-model.js` (pure State + session -> view), `controller.js` (session state machine over core), `ipc.js` (channel table + sender check), `position.js` (pure popover geometry). `fake-core.js` implements the Contract 5 subset in memory and is swapped in with `LEADERBORDER_FAKE_CORE=1`. The renderer is sandboxed, talks only through `preload.cjs`, and renders static per-screen sections filled from the view.

**Tech Stack:** Electron 44 (ESM main, CommonJS sandboxed preload), electron-builder 26, `node:test`, `@playwright/test` 1.63 `_electron`.

**Spec:** `docs/superpowers/specs/2026-09-24-leaderborder-design.md` (packages/app, Distribuce), master plan `docs/superpowers/plans/2026-09-24-leaderborder.md` (Contracts 3, 5, 6).

## Global Constraints

- JavaScript ESM only, Node >= 22; preload is `preload.cjs` because sandboxed preloads cannot be ESM.
- Zero comments by default. Plain hyphen only (never U+2014 / U+2013). All UI copy English.
- No `npm install`, no new deps. No commit, no push, no stash/checkout/reset, no worktrees. Only `git add` own files.
- Edit only `packages/client/src/app/**`, `packages/client/assets/**`, `packages/client/electron-builder.yml`, `packages/client/test/app/**`, this file.
- Core is consumed only through Contract 5 names: `getConfig`, `loadState`, `sync`, `login`, `logout`, `cursorStatus`, `cursorLogin`, `createApi(...).getMe`, `keychain.getToken`.
- Renderer: `contextIsolation: true`, `sandbox: true`, `nodeIntegration: false`, strict CSP, `shell.openExternal` only for `https://`.
- UI uses only Contract 6 token names; temporary `renderer/tokens.css` defines exactly those names.
- `npm run lint` (repo root) and `npm run test -w leaderborder` must pass.

### Task 2: view-model (pure)

**Files:** Create `src/app/view-model.js`; Test `test/app/view-model.test.js`

**Interfaces:**
- `compactNumber(n)` -> `"950"`, `"1.2K"`, `"12.3K"`, `"123K"`, `"1.2M"`, `"1M"` for 999 950, `"2.5B"`.
- `formatCost(usd)` -> `"$0.42"`, `"$12.30"`, `"$1.2K"`.
- `relativeTime(iso, now)` -> `"Never"`, `"Just now"` (< 60 s), `"5 min ago"`, `"3 h ago"`, `"2 d ago"`.
- `errorMessage(error)` -> friendly English copy per `LeaderborderError.code`, fallback to `error.message`.
- `normalizeDeviceCode(arg)` accepts `{ userCode, verificationUri }` or GitHub's `{ user_code, verification_uri }`.
- `toView({ state, session, now })` where `session = { signedIn, syncing, signingIn: { userCode, verificationUri } | null, error: { message } | null, notice: string | null, me: { user, rank } | null, cursor: { loggedIn, busy, hint }, loginItem: { available, enabled } }` returns `{ kind, trayTitle, ... }` with `kind` in `signed-out | signing-in | idle | syncing | error`. Account kinds carry `user`, `today { tokens, cost }`, `week { tokens, cost }`, `topModel`, `rank { label, detail } | null`, `lastSync`, `cursor`, `loginItem`, `errorMessage`.

- [x] Tests for every formatter edge case above and for each `kind`: signed-out (no token), signed-out with notice, signing-in (code present, waiting while code not yet known), idle with summary + rank, idle with `summary: null` (zeros, "Never"), syncing, error from `session.error`, error from `state.lastError` when not syncing; trayTitle `""` signed-out, `compactNumber(today)` signed-in.
- [x] Run -> FAIL; implement; run -> PASS.

### Task 3: scheduler

**Files:** Create `src/app/scheduler.js`; Test `test/app/scheduler.test.js`

**Interfaces:** `SYNC_INTERVAL_MS = 3_600_000`, `STARTUP_DELAY_MS = 10_000`, `RESUME_DELAY_MS = 5_000`; `nextDelay({ lastSyncAt, lastAttemptAt }, now)` -> ms clamped to `[0, SYNC_INTERVAL_MS]`, based on the later of the two timestamps (ISO string or ms), `0` when neither; `createScheduler({ run, now, setTimer, clearTimer })` -> `{ start(), resume(), trigger(), stop(), isRunning() }`.

- [x] Tests: `nextDelay` null -> 0, 10 min ago -> 50 min, 2 h ago -> 0, future (clock skew) -> interval cap, attempt newer than sync wins. Scheduler with fake timers: `start` schedules 10 s; firing runs once and reschedules 60 min; `trigger` while running returns the same promise and `run` is called once; a rejecting `run` still reschedules and clears running; `resume` replaces the pending timer with 5 s; `stop` clears.
- [x] Run -> FAIL; implement; run -> PASS.
