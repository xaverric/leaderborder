# WS E: CI/CD, release packaging, docs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** GitHub Actions CI, nightly security/compat checks, tag-driven release that builds DMGs + npm tarball + rendered Homebrew formula/cask, Worker deploy, and user-facing docs (`README.md`, `docs/RELEASING.md`).

**Architecture:** Five workflows with `permissions: {}` at the top and per-job grants. Jobs that run `npm ci` (third-party install scripts) never hold a write token; the only write jobs (`gh release create`, nightly issue) run no project code. Release packaging logic lives in one pure-function Node script (`scripts/render-homebrew.js`) tested with `node:test`.

**Tech Stack:** GitHub Actions, Node 22 + npm 10 (`.npmrc` `legacy-peer-deps=true`), electron-builder 26, wrangler 4 via `cloudflare/wrangler-action`, CodeQL, OSV-Scanner, gitleaks, Homebrew formula + cask DSL.

**Spec:** `docs/superpowers/specs/2026-09-24-leaderborder-design.md` (Distribuce, CI/CD), master plan `docs/superpowers/plans/2026-09-24-leaderborder.md`.

## Global Constraints

- Edit only `.github/**`, `packaging/**`, `scripts/**`, `docs/RELEASING.md`, `README.md`, this file.
- No `npm install`, no new deps, no commit/push, no worktrees, no releases/secrets/repos created, no workflow runs. `git add` own files only.
- Scripts: plain Node ESM, built-ins only, pure functions + thin CLI. Zero comments by default.
- Never a long dash (U+2014 / U+2013). English.
- Security: least-privilege `permissions:` per job, `concurrency` per workflow, no `pull_request_target`, third-party actions pinned to full commit SHA with `# vX.Y.Z`, `persist-credentials: false`, Node 22 via `actions/setup-node` with `cache: npm`, `npm ci`.
- Untrusted values (`github.ref_name`, `github.head_ref`, inputs) reach shell only through `env:`, never inline `${{ }}` in `run:`.
- Release never publishes to npm or Homebrew.

## Key decisions (from research)

- `npm ci` works on ubuntu: the lockfile carries every `@tokscale/cli-*`, `@cloudflare/workerd-linux-64`, `@esbuild/linux-x64`, `@rolldown/binding-linux-x64-gnu` optional entry. Ubuntu jobs set `ELECTRON_SKIP_BINARY_DOWNLOAD=1` (Electron binary unused there).
- `npm run build:app -- --publish never` at root does NOT forward flags (root script is `npm run build:app -w leaderborder` without a trailing `--`, so npm eats `--publish`). Also WS D's `electron-builder.yml` sets `mac.target: [{ target: dmg, arch: [arm64, x64] }]`, and electron-builder ignores a bare `--arm64` when the config lists archs and the CLI names no target (`targetFactory.computeArchToTargetNamesMap`). So `scripts/build-dmg.sh` runs `npx --no-install electron-builder --mac dmg --<arch> --config electron-builder.yml --publish never` in `packages/client`, which builds exactly one arch. Lead fix requested anyway: root `"build:app": "npm run build:app -w leaderborder --"`.
- x64 DMG on the arm64 runner: electron-builder downloads the Electron zip for the target arch itself (`--x64`), app has no native modules, and its npm collector (`npm list -a --include prod --include optional`) packs whatever is installed. `npm ci` on arm64 skips `@tokscale/cli-darwin-x64` (`os`/`cpu` filter), so the release job fetches it with `npm pack @tokscale/cli-darwin-x64@<lock version>`, checks the tarball `integrity` against `package-lock.json`, and extracts into `node_modules/@tokscale/cli-darwin-x64`. Chosen over `npm install --no-save --cpu=x64` because that re-resolves the whole workspace tree for another CPU (arborist, legacy-peer-deps bug surface) instead of adding one locked package.
- Signing: electron-builder signs when `CSC_LINK` is set and notarizes automatically when `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD`, `APPLE_TEAM_ID` are set (`MacTargetHelper.notarizeIfProvided`, unless `mac.notarize: false`). Job env `SIGNING: ${{ secrets.CSC_LINK != '' }}` exposes only a boolean; the build step receives the actual secrets only when `env.SIGNING == 'true'`, otherwise `CSC_IDENTITY_AUTO_DISCOVERY=false`.
- DMG names: electron-builder `artifactName` belongs to WS D, so the release job finds the one new `*.dmg` after each build (marker file + `find -newer`) and renames it to `Leaderborder-<version>-<arm64|x64>.dmg`. The cask URL depends on exactly these names; `render-homebrew.js` refuses other names.
- Homebrew formula (docs.brew.sh Language-Specific-Formulae): `depends_on "node"`, `system "npm", "install", *std_npm_args(ignore_scripts: false)`, `bin.install_symlink libexec.glob("bin/*")`. `ignore_scripts: false` because the `electron` dependency downloads its binary in `postinstall` and `leaderborder` without args launches the app. URL = GitHub Release tarball (same bytes the user publishes to npm).
- Cask (Cask Cookbook): stanza order `arch`, `version`, `sha256 arm:/intel:`, `url` with `#{arch}`, `name`, `desc`, `homepage`, `livecheck`, `depends_on macos:`, `app`, `zap`, `caveats`. Unsigned app: caveat with `xattr -dr com.apple.quarantine`, no `--no-quarantine` (deprecated in Homebrew).
- `gitleaks-action` needs no license on a personal account (`xaverric` is type `User`).
- deploy.yml runs worker tests before deploying; it is reused by release.yml via `workflow_call` + `secrets: inherit`. Secrets absent -> `::notice::` and success.

### Task 1: Homebrew templates + render script (TDD)

**Files:**
- Create: `packaging/homebrew/leaderborder.rb.tmpl`, `packaging/homebrew/leaderborder-cask.rb.tmpl`, `scripts/render-homebrew.js`
- Test: `scripts/render-homebrew.test.js`

**Interfaces:**
- Produces:
  - `renderTemplate(tpl: string, vars: Record<string, string>) -> string` replaces `{{NAME}}` (`[A-Z0-9_]+`), throws `Missing template variable: NAME`; leaves Ruby `#{...}` untouched.
  - `sha256(buffer) -> hex string`
  - `releaseUrl({ repo, version, file }) -> "https://github.com/<repo>/releases/download/v<version>/<file>"`
  - `dmgFileName(version, arch) -> "Leaderborder-<version>-<arch>.dmg"`; `tarballFileName(version) -> "leaderborder-<version>.tgz"`
  - `homebrewVars({ repo, version, tarballSha256, dmgArm64Sha256, dmgX64Sha256 }) -> { REPO, VERSION, TARBALL_URL, TARBALL_SHA256, DMG_ARM64_SHA256, DMG_X64_SHA256 }`; throws on non-semver version or non-hex sha.
  - `renderHomebrew({ formulaTpl, caskTpl, vars }) -> { formula, cask }`
  - CLI: `node scripts/render-homebrew.js --version X --tarball path --dmg-arm64 path --dmg-x64 path --out dir [--repo owner/name]` writes `<out>/leaderborder.rb`, `<out>/leaderborder-cask.rb`; exit 2 on usage error (missing flag, file basename not matching the expected release name), 1 on IO error.
- Consumed by: release.yml render step.
